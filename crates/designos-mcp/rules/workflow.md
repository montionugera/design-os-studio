## Build-Verify-Fix Workflow

Follow this 7-step loop on every design task in DESIGN:OS Studio:

1. **Orient** — Call {{#if tool:designos_get_document}}{{tool:designos_get_document}}{{/if}}{{#if tool:designos_list_nodes}} and {{tool:designos_list_nodes}}{{/if}} to inspect existing pages, frames, variables, shared styles, and components before creating or modifying anything.
2. **Ground** — Call {{#if tool:designos_get_variables}}{{tool:designos_get_variables}}{{/if}}{{#if tool:designos_get_guidelines}} and {{tool:designos_get_guidelines}} with `topic: "design-system"`{{/if}} to load the file's token sources, component sets, variants, and slot definitions. Never invent raw hex colours, off-scale pixel gaps, or ad-hoc rectangles when a variable, style, or component exists.
3. **Plan** — {{#if tool:designos_get_guidelines}}Pick a vertical archetype ({{tool:designos_get_guidelines}} with `topic: "archetypes"`) or surface guide (`topic: "web-app"`, `"mobile-app"`, `"landing-page"`, `"slides"`, `"table"`) when starting a new screen. {{/if}}Place new top-level frames beside existing frames on the active page — never stack a new screen at `(0, 0)` on top of an existing frame.
{{#if write_tools}}
4. **Build in sections** — {{#if tool:designos_apply_spec}}Pass `in_progress: true` on intermediate {{tool:designos_apply_spec}}{{#if tool:designos_apply_batch}} / {{tool:designos_apply_batch}}{{/if}} calls and `in_progress: false` (or omit) on the final call of a task. Prefer one {{tool:designos_apply_spec}} call per screen section (header, navigation, main card, footer){{#if tool:designos_apply_batch}} or one {{tool:designos_apply_batch}} call per multi-step edit{{/if}} over dozens of single-node calls.{{/if}}{{#unless tool:designos_apply_spec}}{{#if tool:designos_apply_batch}}Use {{tool:designos_apply_batch}} to group multi-step node creation and updates into one atomic transaction per screen section rather than issuing separate single-node calls.{{/if}}{{#unless tool:designos_apply_batch}}Build each screen section methodically using the enabled node mutation tools ({{#if tool:designos_create_node}}{{tool:designos_create_node}}{{/if}}{{#if tool:designos_update_node}}, {{tool:designos_update_node}}{{/if}}), verifying parent containers and auto-layout sizing at each step.{{/unless}}{{/unless}}
5. **Read `issues` on every write** — Every mutating tool response includes `issues: {total, new_in_this_call, items}`. Fix `error`-severity items (`new_in_this_call > 0`) before moving to the next section. When a tool returns an error with `safe_to_retry: true`, apply its `corrected_example` or `valid_options` and retry once; when `safe_to_retry: false`, stop and follow `next_step`.
{{/if}}
6. **Visual check** — {{#if tool:designos_render_png}}Call {{tool:designos_render_png}} on the finished frame and inspect the rendered PNG image for visual hierarchy, alignment, text clipping, and contrast that geometry rules alone cannot catch.{{/if}}{{#unless tool:designos_render_png}}Inspect the frame hierarchy{{#if tool:designos_get_node}} with {{tool:designos_get_node}}{{/if}} for visual hierarchy, alignment, clipping, and contrast.{{/unless}}
7. **Final audit** — {{#if tool:designos_lint}}Call {{tool:designos_lint}} with `preset: "agent"` (or `"strict"` / `"marketing"` when appropriate) and resolve all remaining error-severity findings before reporting completion.{{/if}}{{#unless tool:designos_lint}}Review all modified frames and confirm zero remaining layout, token, or naming issues before reporting completion.{{/unless}}
